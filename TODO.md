- [ ] **[FS] Автоматический Full Screen при переходе на новую страницу**  
  *Приоритет:* 5 (Обычный)  
  *Контекст:* Ранее реализовано для Pinterest. Сейчас элемент Full Screen появился на Grok. На RedGifs фулскрин не сбрасывается сам. Нужна единая общая настройка.  
  *Логика работы:*
  - При включенной опции FS, если происходит автоматический переход на новую страницу (в рамках слайдшоу) либо переход после нажатия кнопки «Скачать» (если в настройках задан переход `pdAction`):
  - Попытаться найти кнопку Full Screen / «Во весь экран» и нажать её.
  - Страница прогружается не мгновенно, поэтому делать **3 попытки**:
    1. Через **100 мс**
    2. Через **300 мс** (+200 мс)
    3. Через **500 мс** (+200 мс)
  - Если на каком-то сайте фулскрин сохраняется нативно — пользователь просто не включает эту опцию для этого домена.

## 🤖 Тудушки для Grok (`grok.com`)

- [ ] **[Звук / ScrollLock] Корректный Mute / Unmute в плеере Grok**  
  *Приоритет:* 5 (Обычный)  
  *Проблема:* При нажатии `ScrollLock` включается звук вкладки в обход плеера Grok. При этом сам плеер остаётся визуально замьюченным, а последующий клик мыши по плееру приводит к рассинхрону и путанице.  
  *Решение:* Перехватывать `ScrollLock`, находить в DOM плеера кнопку громкости / включения звука («Включить звук» / «Выключить звук» / mute/unmute SVG) и программно кликать именно по ней.

- [ ] **[Удаление / a.confirm] Автоподтверждение удаления**  
  *Приоритет:* 5 (Обычный)  
  *Контекст:* Опция `a.confirm` в панели настроек.  
  *Логика работы:*
  - При нажатии клавиши `Delete` (если чекбокс `a.confirm` активен), Grok через небольшую паузу показывает модальное окно с предупреждением («Это действие необратимо») и кнопками «Отменить» и «Удалить изображение» (для фото) или «Удалить видео» (для видео).
  - Скрипт должен искать кнопку подтверждения с текстом «Удалить изображение» или «Удалить видео» по таймингам:
    - 1-я проверка: через **100 мс**
    - 2-я проверка: через **300 мс**
    - 3-я проверка: через **500 мс**
  - При обнаружении кнопки — немедленно кликать подтверждение.

- [ ] **[Удаление / hold post] Умное удержание позиции в ленте при удалении**  
  *Приоритет:* 5 (Обычный)  
  *Проблема:* Когда пост удаляется, Grok автоматически перебрасывает курсор/просмотр в самый конец ленты — к последней сгенерированной генерации. Просмотр текущей подгруппы сбивается.  
  *Алгоритм решения (`hold post`):*
  1. Пользователь нажимает `Delete` на текущем посте (например, пост №5).
  2. Скрипт НЕ удаляет пост сразу, а делает **1 шаг по направлению D-pad** (например, стрелка влево/вверх на пост №4).
  3. Считывает и запоминает целевой URL поста №4.
  4. Возвращается назад на удаляемый пост №5.
  5. Запускает удаление поста №5 (если включен `a.confirm` — подтверждает).
  6. Ждёт изменения URL: когда Grok удалит пост №5, он сам начнёт перебрасывать страницу в конец ленты.
  7. Как только URL изменился (стал отличаться от №5) — скрипт мягко переходит (желательно без полной перезагрузки страницы) на сохранённый целевой URL поста №4.
  8. **Результат:** пост удалён, но мы остались ровно на следующем по порядку посте и продолжаем просмотр без улёта в конец ленты.
